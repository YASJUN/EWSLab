# EWSLab

[简体中文](README.md) | **日本語** | [English](README.en.md)

Android 向けの独立したアナログ音声 EWS（緊急警報放送）受信・解析プロジェクトです。JMA 津波電文から信号音を生成するオフラインツールも含みます。Android 10（API 29）以降に対応します。

上流の Git 履歴を保持して書き直した実装です。アプリ名とアプリケーション ID を分離しているため、従来の EWSParserApp と共存できます。現在は **0.1.0 実験版**です。オフラインでの復号成功は、スマートフォンの音響経路や実機 EWS 受信機の起動を検証済みであることを意味しません。

## ダウンロードとインストール

- [v0.1.0 プレリリース：APK、オフライン生成器、SHA-256 チェックサム](https://github.com/YASJUN/EWSLab/releases/tag/v0.1.0)
- Android パッケージ：`EWSLab-0.1.0.apk`。アプリケーション ID は `xyz.ckkpd.ewsparserapp.lab` です。
- APK は専用のリリース鍵で署名した release ビルドです。同じアプリケーション ID の debug 版をインストール済みの場合は、先に debug 版をアンインストールしてください。従来の EWSParserApp は別の ID なので共存できます。
- Android の案内に従い、使用するブラウザーまたはファイル管理アプリからの APK インストールを許可してください。録音権限が必要なのはマイク受信時のみです。アプリの UI は現在、簡体字中国語です。3 言語対応は README のみです。
- 添付の `SHA256SUMS.txt` で APK と生成器のハッシュを確認できます。署名・ビルド・公開手順は[リリース手順（中国語）](docs/releasing.md)を参照してください。

## 使い方

1. 上記の Release から `EWSLab-0.1.0.apk` をダウンロードしてインストールします。または `EWSLab-debug.apk` を自分でビルドしてローカルでデバッグできます。
2. 「导入 WAV 文件」で生成器の PCM16 WAV を選択します。マイク受信の場合は「开始接收」を押し、録音権限を許可してテスト音声を再生します。
3. 単一ブロックの候補／連続確認、地域、符号化時刻、2 つの保護ビット、6 個の生の 16 ビットワードを確認します。
4. 停止操作またはアプリが前面から外れると入力を停止します。履歴はメモリー内のみです。画面回転時はセッションを終了し、画面を再生成します。

時刻は「西暦の下一桁・月・日・時（JST）」で表示します。EWS は分・秒や完全な西暦を伝送しないため、この表示は端末時計の異常ではありません。時の境界付近では、奇数・偶数の保護ブロックが正当に 1 時間異なることがあり、午前 0 時をまたぐ場合は日付も変わります。

生成器は `generator/ews_tsunami_player.html` を開くだけでオフライン利用できます。npm や Web サーバーは不要です。既定の時刻ソースは画面表示を確認してください。電文の事例を再現する場合は電文時刻に切り替え、「实际编码时间（JST）」を確認します。

## ディレクトリー

- `core/`：Android に依存しない Java 受信コア。厳密なフレーム解析、連続確認、多位相復調、ストリーミング WAV 読み込み。
- `app/`：ネイティブ Android UI、前面でのマイク入力、システムファイル選択、入力レベルと診断。
- `generator/`：検証対象の単一 HTML 生成器のコピー。元の外部ファイルは変更していません。
- `scripts/`：再現可能なビルドと、生成器・受信コアの言語をまたぐ統合テスト。
- `docs/protocol.md`：プロトコル、アルゴリズム、出典（中国語）。
- `docs/verification.md`：実施した検証、制限、端末検証手順（中国語）。
- `docs/privacy.md`：権限とプライバシー（中国語）。
- `docs/releasing.md`：リリースビルド、署名、チェックサム（中国語）。

## ビルドとテスト

JDK 17 または 21、Android SDK プラットフォーム `android-37.0`、Build Tools 36.0.0 が必要です。生成器との統合テストには Node.js 22 も必要です。Gradle Wrapper 8.14.3 を同梱し、公式配布物の SHA-256 を固定しています。AGP は 8.13.0、JUnit は 4.13.2 に固定しています。

Android Studio でプロジェクトを開いて SDK を設定するか、`ANDROID_HOME` を設定するか、Git 管理対象外の `local.properties` に `sdk.dir` を設定してください。

Windows では、中国語を含むチェックアウトパスに対応した次の入口を推奨します。

```powershell
.\scripts\build.ps1
```

このスクリプトは全テスト、lint、APK ビルドを実行します。パスに中国語などを含む場合、中間出力をプロジェクトパスのハッシュで分けた ASCII の一時ディレクトリーに出力します。`-BuildRoot` による指定も可能です。最終的な debug APK は `verification/local/EWSLab-debug.apk` にコピーされます。ビルド出力先にソースディレクトリーを指定しないでください。

通常のパス、Linux、macOS では標準の Wrapper を使用できます。

```sh
./gradlew :core:test :core:verifyGenerator :app:lintDebug :app:assembleDebug
```

Node.js や生成 WAV を使わずに、独立した JVM 回帰テストのみを実行する場合：

```sh
./gradlew :core:test
```

統合テストは `node scripts/generator-check.cjs` で 26 個の WAV を生成し、同じ受信コアで 242 個の本体をフィールドごとに検証します。生成物は Git 管理対象外の `verification/local/` に保存します。失敗をスキップしたり、成功として扱ったりしません。

lint は `warningsAsErrors` を有効にし、baseline は使用していません。既知のツール警告として、AGP 8.13.0 の公式テスト対象上限が SDK 36.1 である一方、使用する SDK が 37.0 であること、Windows の中国語パスで `android.overridePathCheck` が必要であることが表示されます。ビルドと lint は成功していますが、Android 17 の全動作に対応済みとは主張しません。今後の安定版公開前に、対応する AGP／SDK の組み合わせで再検証する必要があります。警告は隠していません。

## 元の実装からの変更

- 録音の読み込みが常にバッファー全体を返すとは仮定せず、不明な検査符号をワイルドカードとして受け入れません。
- 8 つのビット位相を継続探索し、正確な 640/1024 Hz の Goertzel 法と相対エネルギー判定を使用します。小数サンプルのビットクロックと破損ブロック後の再同期に対応します。
- 3 つの固定符号、フィールド識別、規定の 53 地域符号、日付・年時の符号語を検証します。
- 同じ物理ブロックの多位相結果を重複排除してから連続確認します。破損、長い間隔、種別・地域の変化、不自然な時刻変化で確認をリセットします。
- 単一ブロックは候補として扱います。EWS 自体に CRC はなく、有効な符号語同士の誤りをすべて検出できるわけではありません。
- 終了ブロックの 92 ビット相当の無音中もクロックを進めます。マイクと WAV は同じコアを使用します。
- 警報の自動再生、ネットワーク通信、バックグラウンド常駐、マイク録音の保存は行いません。
