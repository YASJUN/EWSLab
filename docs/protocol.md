# 协议与接收设计

## 依据及边界

协议依据日本总务省告示第405号《無線設備規則第九条の三第五号の規定に基づく緊急警報信号の構成》：
https://www.tele.soumu.go.jp/horei/law_honbun/72103000.html

关联规则：無線設備規則第9条の3、無線局運用規則第138条の2。源码对照项目及许可溯源在 `NOTICE.md`。这些是模拟广播音频 EWS 符号，不是数字广播 EWBS 标志或手机 EEW 推送。

此前用户粘贴的任务描述只是待核查假设，其中“0xAA 前导”“0x33 海啸”“第二种仅训练”“4-of-8 每字节重复”等假设均未作为实现依据。本接收器按以下实际结构处理。

## 位与字段

- 64 baud，640 Hz 对应 0，1024 Hz 对应 1，音调相位连续。
- 第一种开始固定码与结束固定码为 `0000111001101101`（0E6D）。第二种开始为 `1111000110010010`（F192）；海啸使用第二种。
- 主体为 `固定16 + 地域16 + 固定16 + 月日16 + 固定16 + 年时16`，共 96 位。
- 开始地域：`10 + area12 + 00`；月日：`010 + day5 + dateFlag + month5 + 00`；年时：`011 + hour5 + hourFlag + year5 + 00`。
- 结束地域：`01 + area12 + 11`；月日：`100 + day5 + dateFlag + month5 + 11`；年时：`101 + hour5 + hourFlag + year5 + 11`。
- 开始发送一次 `1100` 后连续重复主体，默认 10 块、964 位。
- 结束的每个周期为 `0011 + 主体96 + 92位时长静音`，每周期 192 位时隙，默认 4 周期。

码表保持空中先后位序，不统一按十进制直写或把整串盲目翻转。地域共通为 `001101001101`（34D）；核心还包含 5 个广域码与 47 个县域码，共 53 个，县域码逐行来自告示别表第1号。生成器当前只开放地域共通和 5 个广域。

独立基准：2024-01-01 16:12 JST、地域共通、第二种，前置符号后六字为：

```text
F192 8D34 F192 5044 F192 6214
```

## 时间保护

奇数块始终对应当前发送时刻，保护位为 0。偶数块在 00..09 分使用上一小时，在 50..59 分使用下一小时，在 10..49 分使用当前小时；跨午夜时同时改变日期及日期保护位。年码只恢复公历末位；不使用设备当前年份冒充报文完整年份。

日期检查允许最多 2 月 29 日，因为仅有年末位通常不能确定是否闰年；但奇数年末位必然不是闰年，因此拒绝对应的 2 月 29 日。对于需要跨日比较的相邻保护块，分别检查闰年与非闰年日历的可能性，不猜测世纪。

## 接收流程

`AudioDecoder` 为每个输入维护八个位时钟相位。每个位窗口以精确音频频率进行 Goertzel 计算，依据音调能量占比、两频比和最低数值底噪决定 0、1 或未知。窗口边界按绝对小数采样位置取整，避免每位截断误差累积。

各相位始终运行独立的滑动 `FrameParser`。每个位或静音时隙都推进解析器；完整 96 位主体必须通过三次固定码一致、字段边框一致、码表和日历检查。允许在缺失最初四位前置符号时恢复后续主体，但结果明确标记前置符号未验证。

同一主体在各相位上的候选按1.25个位时长的时间窗聚合，选择平均音调能量质量更高的结果，仅输出一次。随后使用物理块间隔（开始约96位、结束约192位）、类型、地域和时间关系累计连续确认；不得把同一物理块的多个相位算成多块。

这是持续多相位搜索与逐块重同步，不宣称实现了完整 PLL、均衡器或任意漂移范围。已验证 ±1000 ppm；超出范围、强混响、削顶、手机降噪或不平衡双声道相消均可能使接收失败。双声道 WAV 以两声道算术平均下混。

`flush()` 只输出已经完整接收的待聚合主体，不补造缺失采样。一个有效主体是候选；连续确认也不是硬件起动认证、EWS CRC 或播出真实性认证。
